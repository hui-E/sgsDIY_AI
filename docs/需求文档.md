# 三国杀武将 DIY — 需求文档

## 1. 项目概述

开发一款“三国杀武将卡 DIY”应用，让用户输入武将信息并上传武将图片，经过两阶段（编辑信息 → 排版）后，导出一张固定尺寸的武将卡图片保存到相册。

最终交付形态：Web 版编辑器先行跑通（手机浏览器可直接使用），再通过 Capacitor 打包为 Android APK。

## 2. 范围与目标

**核心目标**

- 第一阶段：录入武将名称、称号、血量、技能（可动态增删）、势力、上传武将图片。
- 第二阶段：拖动/缩放布局，导出固定尺寸卡面图片。
- 卡面默认尺寸：1425 × 2048（竖版），导出时按该分辨率输出。

**明确不做（本期）**

- 不含“神”势力。
- 不提供拍照，仅相册选图。
- 不做官方卡牌数值平衡、联网对战、卡组管理。

## 3. 功能需求

### F1 编辑信息（第一阶段）

用户填写以下信息：

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| 武将名称 | 卡面竖排主标题 | 非空 |
| 称号 | 卡面竖排副标题 | 可空 |
| 血量 | 勾玉数量 | 0 ~ 10 整数 |
| 技能 | 技能名 + 技能描述，见 F1.1 | 1 ~ 3 个 |
| 势力 | 选择势力 | 魏 / 蜀 / 吴 / 群 / 晋 |
| 武将图片 | 从相册选取 | 必传后进入排版 |

#### F1.1 技能动态增删

- 最少 1 个，最多 3 个。
- 提供“新增技能 / 删除技能”按钮，动态增删。
- 有几个技能，卡面就渲染几个技能框 + 描述，自上而下堆叠。

#### F1.2 势力选择

- 五选一：魏、蜀、吴、群、晋。
- 势力决定：卡面左侧立板边框、势力徽记、勾玉配色、技能框配色。
- 徽记已内置于边框素材 `wei/shu/wu/qun/jin.png`，无需单独绘制。

### F2 排版（第二阶段）

用户点击“下一步”进入排版画布。画布即 1425 × 2048 卡面。

#### F2.1 可移动元素

以下三项可拖动（改变位置）：

- 武将名称
- 称号
- 武将图片（可拖动 + 双指缩放）

#### F2.2 不可移动元素（固定）

- 势力边框立板与徽记
- 勾玉（血量）
- 技能框 + 技能描述区

以上按势力模板自动排版，用户不可移动。

#### F2.3 双层图片模型

右侧武将图区域采用“双图层”模型：

- 上图层：卡框（边框、勾玉、技能区、装饰），固定，不随图片移动。
- 下图层：武将图片，可拖动、可双指缩放。
- 卡框区域为“有效区域”：图片超出卡框有效区域的部分在导出时被裁剪，保证每张卡固定为 1425 × 2048。

即在预览时图片被限制在卡面窗口内显示，拖动/缩放本质是调整图片在窗口内的位置与大小，导出只会输出窗口内的内容。

#### F2.4 技能框动态对齐

- 技能框本身不能被用户移动。
- 每个技能框需始终对齐到该技能描述文本**首行起始位置（左侧）**。
- 技能描述字数多导致换行时，首行起点可能不同，技能框需**自动计算并跟随对齐**（水平左对齐，垂直对齐到该技能描述块的首行/整块）。
- 技能区域整体自上而下自动排布，随技能数量与描述高度自适应。

#### F2.5 文字排版

- 武将名称、称号默认竖排（自上而下逐字），与成品参考一致，可整体拖动。
- 文字大小、描边、样式随模板固定，提供合理默认值；后续可扩展字号调节。

### F3 保存导出

- 点击“保存”把当前卡面渲染为 1425 × 2048 图片。
- Web 版：下载 PNG（移动端可保存到相册 / 分享）。
- APK 版：写入系统相册（需相册写入权限）。
- 导出内容 = 固定卡框 + 有效区域内可见的武将图片 + 可移动文字位置。


### F4 AI 设计（自动生成武将卡文字内容）

> 目标：玩家只需输入一个“人物名”，AI 按严格约束返回标准 JSON，前端自动把内容填入编辑表单，再走原有排版导出流程。

#### F4.1 用户输入

- 仅需输入人物名，例如 `黑崎一护` 或带出处的 `《死神》黑崎一护`。
- 不要求用户填写称号 / 势力 / 血量 / 技能等任何其他字段。

#### F4.2 提示词模板

发送给 AI 的提示词以“约束条件 + JSON 字段规范”为主体，要求：

1. 输出 JSON 必须包含字段：人物名称、称号、势力、勾玉数（体力值）；技能数量不超过 3 个。
2. 每个技能名称严格为两个汉字；全部技能描述合计总字数不超过 300 字。
3. 参考人物原作百科设定，技能贴合人物能力；技能文本严格遵循三国杀官方技能表述规范，使用官方术语（锁定技、限定技、出牌阶段限一次、当XX时等），对标官方原版武将格式。
4. 参考三国杀官方现有武将卡牌的设计逻辑与措辞。
5. 势力只能从 `魏 / 蜀 / 吴 / 群 / 晋` 中五选一。
6. 只输出标准 JSON，不要任何前言、解释、markdown、额外说明文字。

#### F4.3 返回 JSON 字段

```json
{
  "character_name": "人物名称",
  "title": "人物称号",
  "camp": "势力",
  "hp": 勾玉数,
  "skills": [
    { "name": "两字技能名", "desc": "三国杀规范技能描述文本" }
  ]
}
```

- `skills` 允许 `1 ~ 3` 个，返回 1 个不报错，正常填入。

#### F4.4 前端自动回填

- 收到合法 JSON 后，自动把 `character_name / title / camp / hp / skills` 填入编辑表单。
- 势力映射为内部 key `wei / shu / wu / qun / jin`；AI 未按五选一返回时自动映射为「群」。
- 勾玉数超过上限自动映射为上限（10）；低于下限（<1）或非数字自动映射为默认值（1）。
- 技能名不为两字、描述超 300 字时做自动容错（超长截断并保留，非两字技能名按原样或截断处理），不抛错。
- 回填后仍允许用户手动修改、增删技能、继续执行排版与导出。

#### F4.5 AI 调用配置

- 用户提供 OpenAI 兼容格式：`base URL`、`API Key`、`模型名`。
- 配置保存在本地：Web 版用 `localStorage`，APK 版用本地存储；持久化，无需每次打开重复填写。

#### F4.6 网络通道（CORS 兼容）

- 默认前端直接 `fetch` 用户配置的 base URL。
- 当运行在 `localhost` 调试且直连被 CORS 拦截时，自动切到本 [server.js](D:/projects/sgsDIY_AI/server.js) 的 `/api/ai/design` 代理。
- APK（Capacitor）内使用原生 HTTP 通道，绕开浏览器 CORS 限制。

#### F4.7 校验与容错（不硬报错）

- AI 输出可能带 ```json 代码块或前后缀说明：解析时先剥离代码块标记，再提取首个 `{` 到末个 `}`。
- 任一字段缺失 / 非法：使用默认值回填（势力→群、hp→1、称号→空、技能缺失→跳过）。
- 全部解析失败时，仅在界面给出温和提示（“未获取到有效内容，请重试”），不影响原有手动编辑。

## 4. 数据模型

```ts
type Faction = 'wei' | 'shu' | 'wu' | 'qun' | 'jin'

interface Skill {
  name: string
  desc: string
}

interface Transform {
  x: number      // 相对卡面的 x（逻辑坐标）
  y: number      // 相对卡面的 y（逻辑坐标）
  scale: number  // 缩放倍率
}

interface GeneralCard {
  faction: Faction
  name: string
  title: string
  hp: number            // 0..10
  skills: Skill[]       // 1..3
  image: ImageBitmap | null
  layout: {
    name: Transform
    title: Transform
    image: Transform
  }
}

// —— AI 设计相关 ——
interface AIConfig {
  baseUrl: string   // OpenAI 兼容 base URL
  apiKey: string    // API Key（仅本地保存）
  model: string     // 模型名
}

interface AISkill {
  name: string      // 两字技能名
  desc: string      // 三国杀规范技能描述
}

interface AICardResult {
  character_name: string   // 人物名称
  title: string            // 人物称号
  camp: string             // 魏 / 蜀 / 吴 / 群 / 晋
  hp: number               // 勾玉数
  skills: AISkill[]        // 1 ~ 3 个
}
```

## 6. 界面流程

```
阶段一（信息编辑）
  表单：名称 / 称号 / 血量 / 技能列表 / 势力 / 选择图片
        └→ 点“下一步”校验（名称、图片必填，技能 ≥1）
阶段二（排版）
  画布：拖名称 / 拖称号 / 拖图 + 双指缩放图 → 点“保存”
        └→ 导出 1425×2048 PNG
```

## 7. 交互与手势

- 名称 / 称号：单指拖动。
- 武将图片：单指拖动 + 双指缩放（以手指中心为缩放锚点）。
- 保存：点击“保存”，渲染并导出。
- 上一阶段 / 重新编辑：可从排版返回编辑，保留已填数据。

## 8. 非功能需求

- 导出分辨率固定 1425 × 2048，不随屏幕缩放。
- 中文字体：保证名/称号使用书法风字体、描述使用清晰字体；导出前确保字体已加载，避免导出空白文字。
- 移动端优先，桌面浏览器同样可用（响应式布局）。
- 素材本地打包，无运行时外部资源依赖（避免弱网导致素材缺失）。
- 编辑中间态可本地持久化（可选，后期）。
- AI 调用需处理 CORS：浏览器调试经本地 `server.js` 的 `/api/ai/design` 代理，APK 走原生 HTTP。
- AI 输出需做严格解析与容错（JSON 提取、字段默认值、超长截断），不合规输出不崩溃、不阻塞手动编辑。
- API 密钥仅保存在本地，不回传。

## 9. 设计假设（如需调整请告知）

1. 默认势力为“蜀”（与成品参考一致）。
2. 名称 / 称号默认竖排，与参考一致。
3. 勾玉从左上角开始横向铺开，数量多时自动换行或收紧间距。
4. 技能描述区底部使用半透明深色底（与参考一致），文字为白色，叠加在武将图上。
5. 武将图片初始状态为“铺满并居中（cover 适应）”卡面有效区域，可再拖动/缩放。
6. 应用名暂定“三国杀武将 DIY”，Capacitor 包名暂定 `com.sgsdiy.app`。
7. 名称 / 称号仅支持拖动，本期不做缩放/旋转；字号调节作为后期扩展。

## 10. 技术方案

- Web 编辑器：HTML5 Canvas 渲染 + 原生交互（拖拽/双指缩放），单页应用。
- 素材预处理：把 `miscellaneous.png` 切分为独立技能框 / 勾玉素材，随应用打包。
- Capacitor 打包 APK：调用相册选图、相册写入插件，配置图标 / 启动屏。
- 代码结构见《开发计划》。
