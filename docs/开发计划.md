# 三国杀武将 DIY — 开发计划

## 目标与原则

- 先做 Web 版跑通，再打包 APK。
- 核心链路（编辑信息 → 排版 → 导出图片）优先做完，再做打包与美化。
- 新增 AI 设计能力：输入人物名 → AI 按严格约束生成文字内容 → 自动填入编辑表单，再复用现有排版导出。
- 素材资源本地打包，不依赖运行时外部网络。

## 项目结构（规划）

> 说明：Web 前端源码实际位于 `public/js/`（`main.js`、`data.js`、`render.js`、`export.js` 等）；本地静态服务器为根目录 `server.js`。AI 调试代理新增于 `server.js` 的 `/api/ai/design`，前端 AI 模块位于 `public/js/ai.js`。

```
sgsDIY_AI/
├─ docs/                  # 需求文档 / 开发计划
├─ 素材/                  # 原始素材（已提供）
├─ public/
│  └─ assets/             # 预处理后的切片素材（skillbox_*, gem_*）
├─ src/
│  ├─ main.js             # 入口 + 路由（阶段一/阶段二）
│  ├─ data.js             # 数据模型 + 默认值
│  ├─ assets/             # 素材加载 / 切片
│  ├─ editor/
│  │  ├─ render.js        # Canvas 渲染管线
│  │  ├─ transform.js     # 拖拽 / 双指缩放（阶段二）
│  │  └─ layout.js        # 技能框动态对齐、勾玉排布
│  ├─ export.js           # 导出 1425×2048 PNG
│  └─ ui/                 # 表单、图片选择等组件
├─ index.html
└─ package.json
```

> 采用原生 JS + Canvas 即可满足；后续若需要更复杂状态管理再引入框架。

## 里程碑与优先级

### Phase 1：Web 版核心链路（先完成）

1. **素材预处理**
   - 把 `miscellaneous.png` 按行、按左右切分为 `skillbox_*`、`gem_*`。
   - 核实各势力立板 PNG 透明区与卡片坐标系。
2. **数据模型 + 阶段一表单**
   - 名称、称号、血量(0~10)、势力(五选一)。
   - 技能动态增删（1~3）。
   - 相册选图（`<input type=file accept=image/*>`）。
   - “下一步”校验：名称、图片必填，技能 ≥1。
3. **Canvas 渲染管线**
   - 画布 1425×2048；分层：武将图(下) → 边框立板/徽记 → 勾玉 → 技能区 → 名称/称号(上)。
   - 中文书法字体加载，导出前确保就绪。
4. **阶段二排版交互**
   - 名称 / 称号拖动。
   - 武将图拖动 + 双指缩放，裁剪到卡面有效区域。
   - 勾玉自动排布。
   - **技能框动态对齐**：每框对齐该技能描述首行左端，随换行自适应。
5. **保存导出**
   - 渲染到离屏 Canvas，输出 1425×2048 PNG。
   - Web 下载 / 移动端保存到相册。
6. **响应式 + 预览验证**
   - 手机浏览器可流畅使用；截图核对成品效果与参考一致。

**Phase 1 完成标志**：能选图 → 填信息 → 排版 → 保存一张边界正确、框对齐、配色正确的卡面图。

### Phase 3：AI 设计（规划，未开始）

> 目标：输入人物名，AI 按严格约束输出标准 JSON，自动回填编辑表单。本阶段尚未开始编码。

1. **AI 配置管理**
   - 填 OpenAI 兼容 `base URL`、`API Key`、`模型名`。
   - Web 版存 `localStorage`；APK 版本地持久化。
2. **提示词构造**
   - 套用严格约束模板（五选一势力、两字技能名、描述 ≤300 字、官方术语、仅输出 JSON），参数化人物名。
3. **网络层（CORS 兼容）**
   - 前端直连配置的 base URL；`localhost` 调试被 CORS 拦截时自动切本地 `/api/ai/design` 代理。
   - APK（Capacitor）用原生 HTTP 通道。
4. **结果解析与容错**
   - 剥离 ```json 代码块、提取 JSON；缺失/非法字段映射默认值（势力→群、hp→上限或 1）。
   - 技能数 1 ~ 3，超长描述截断；全程不硬报错，解析失败仅温和提示。
5. **前端回填**
   - AI 结果自动填入编辑表单；势力映射 `wei/shu/wu/qun/jin`。
6. **交互入口**
   - 编辑页“AI 设计武将”与“AI 配置”两个独立入口。
   - “AI 生成”独立页面：人物名 + 生成/停止 + 进度 + 思维链（最新一行 + 可展开完整历史）。
   - “AI 配置”独立页面：API 地址 / Key / 模型名 + 保存配置。
7. **验证**
   - 用真实 OpenAI 兼容接口跑通，核对 JSON 解析、回填与容错。

### Phase 4：AI 武将图片（本期新增）

> 目标：AI 生成后根据人物名获取人物图像作为卡面图，并提供「换一张」。

1. **配置项**
   - AI 配置页新增「图片服务 ID / 图片服务 Key」，存入 `sgsAiConfig.imgId / imgKey`。
2. **图像服务（浏览器代理）**
   - `server.js` 新增 `/api/img/search`：接收 `words / page / id / key`，转发到 `cn.apihz.cn`。
   - `server.js` 新增 `/api/img/proxy`：下载图片字节回传，同源避免 canvas 污染。
3. **Capacitor 原生通道**
   - `capacitor.config.json` 开启 `plugins.CapacitorHttp.enabled = true`。
   - APK 内搜索与图片走原生 `CapacitorHttp`，图片字节转 `Blob → objectURL`。
4. **前端逻辑**
   - `applyAIResult` 成功后按人物名自动搜第 1 页，取第 1 张设为卡面（cover 居中）。
   - 图片行新增「换一张」按钮（默认隐藏）；游标推进，当前页用尽 `page + 1`。
   - 手动相册选图后隐藏「换一张」。
   - 全程容错：缺配置 / 失败 / 空结果 / 解析失败不阻塞，仅 toast。
5. **验证**
   - 浏览器：配置真实 id/key，AI 生成后自动出图；连点「换一张」至翻页；手动相册后按钮隐藏；导出 PNG 正常。

## 风险与注意点

- 中文字体导出：字体未加载会导致导出文字缺失，必须在导出前 `document.fonts.ready`。
- 双指缩放在手机上依赖触摸事件（touchstart/move/end），需考虑桌面鼠标单一拖动兼容。
- `miscellaneous.png` 切片需像素级校验，避免把勾玉与技能框切坏。
- 导出尺寸较大（1425×2048），移动端 canvas 需注意内存，必要时用离屏 canvas + `createImageBitmap`。
